QuickImport 0.96 is a large release: the first one since v0.95, and most of
the app has been reworked underneath. Importing is considerably faster, the
copy pipeline is safer, and the interface now speaks four languages.

**Note on the version number:** the internal numbering had briefly drifted to
0.7.x, which was *lower* than the released v0.95. This release corrects that
and continues from 0.95.

## Highlights

**Four languages.** The interface is available in English, Dutch, German and
Spanish — all 111 interface strings translated. A language picker sits at the
top of the right-hand pane; the change applies immediately, no restart. Leave
it on "System language" to follow macOS.

**Faster imports.** EXIF parsing when loading a card now runs in parallel
instead of one file at a time. The copy pipeline reads each file once and
hashes it while writing, so importing with MD5 verification enabled is up to
twice as fast. Copy workers pull from a shared queue and a second worker
starts only on fast readers.

**Safer copying.** Each file is written to a temporary file, verified by size
and MD5, and only then renamed into place. The source is deleted only after
the copy — and the backup copy, when enabled — has been verified, and only
after the data has been flushed to physical storage.

**Snappier preview.** A persistent loader thread with a ~100 MB cache and
prefetching of neighbouring images makes browsing with the arrow keys close to
instant. The divider between the file table and the preview is now adjustable,
and its position is remembered.

## Fixed

Crashes on quit after an import, when cancelling a copy, on the "No Card
found" dialog, and in the disk-event callback. Cards from Thunderbolt/PCIe
readers (CFexpress) were not detected, and insertion detection was
timing-dependent — both fixed, without the duplicate prompts. EXIF values were
wrong for big-endian files (Nikon NEF), and files with non-ASCII paths were
not read at all. A failed import used to open one dialog per file; there is
now a single summary. Date-based grouping and filename tokens now both use the
capture time. Buttons are drawn correctly on macOS 26.

## Requirements

macOS 14.0 or newer, Apple Silicon or Intel.

The app is **ad-hoc signed, not notarised**, so macOS blocks it on first
launch with "Apple could not verify ... is free of malware". To open it:
double-click once and dismiss the warning, then go to **System Settings →
Privacy & Security**, scroll down and click **Open Anyway**. (Control-clicking
the app and choosing *Open* no longer works: macOS 15 removed that shortcut.)

Nothing is wrong with the download — it only means the app is not signed with
a paid Apple Developer ID certificate.

## Known issues

- Under VoiceOver, or any tool that reads the full accessibility tree, the app
  can crash inside Qt's macOS accessibility layer. Not reproducible on demand;
  normal mouse and keyboard use is unaffected.
- The summary dialog after a failed import lists full file paths, which makes
  it wider than it needs to be.
