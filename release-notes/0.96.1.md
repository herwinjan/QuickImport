QuickImport 0.96.1 is a small release with one new feature: the app can now
start itself when you insert a memory card.

## New

**Start QuickImport when a card is inserted.** A new checkbox in Import
Settings. Tick it once and QuickImport opens by itself whenever a memory card
is mounted, straight into the card so you can pick the photos and import.
Untick it to switch the behaviour off again.

Under the hood this installs a small per-user launch agent
(`~/Library/LaunchAgents/nl.steehouwer.quickimport.cardwatch.plist`) that
watches for new volumes. A few details worth knowing:

- Only writable FAT/exFAT volumes count as a card. Other disks, disk images
  and unmounts do not open the app: when started for one of those it quits
  again silently. The same goes for a card you have already looked at: if
  you quit QuickImport and leave the card in the reader, it stays quiet
  until you insert a card again.
- If QuickImport is already running, nothing is started and the window is
  left alone. The usual "open the newly inserted card?" question appears
  and brings the window forward.
- The agent points at the copy of QuickImport you ticked the box in. If you
  move or replace the app, it repairs the agent the next time it starts.
- The checkbox shows whether the agent is actually installed, so it stays
  correct even if you remove the agent by hand.

The checkbox is macOS only.

## Requirements

macOS 14.0 or newer, Apple Silicon (M1 or later). Intel Macs are not
supported: this build is arm64 only.

The app is **ad-hoc signed, not notarised**, so macOS blocks it on first
launch with "Apple could not verify ... is free of malware". To open it:
double-click once and dismiss the warning, then go to **System Settings →
Privacy & Security**, scroll down and click **Open Anyway**. (Control-clicking
the app and choosing *Open* no longer works: macOS 15 removed that shortcut.)

Nothing is wrong with the download — it only means the app is not signed with
a paid Apple Developer ID certificate.

## Known issues

- Under VoiceOver, or any tool that reads the full accessibility tree, the app
  can crash inside Qt's macOS accessibility layer. Not reproducible on demand;
  normal mouse and keyboard use is unaffected.
- The summary dialog after a failed import lists full file paths, which makes
  it wider than it needs to be.
